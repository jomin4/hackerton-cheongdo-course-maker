# MVP 명세

> 상태: 확정 (v2 하루 일정) · 최종 수정 2026-11-01 · 설계: [`day-course-design.md`](day-course-design.md)

## 목표

자가용으로 청도에 당일치기로 오는 사람이 방문 날짜 · 시작 · 끝 시각과 동행 · 관심사를 고르면, 그날 문을 연 곳만으로 관광 · 점심 · 쉬어 가기 · 저녁 · 야간 관광이 시각과 함께 적힌 하루 일정을 받아 본다.

## 사용자

- 대구 · 부산 · 울산 등 근교에서 **자가용으로** 당일치기로 오는 개인 · 커플 · 가족 · 친구
- 청도를 처음 방문하거나 동선 · 식사 · 운영시간을 직접 맞추기 귀찮은 사람
- 주 사용 기기: 휴대폰 (모바일 우선으로 확인)

## 기능 목록

| ID | 우선순위 | 기능 | 설명 |

| F3 | P0 | 일정 요약 | 일정 시작–끝, 체류 · 이동 · 여유 시간 막대, 관광 곳 수, 식사 횟수, 안내 문장(`notices`) |

관심사 태그: `nature` 자연 · `history` 역사·문화 · `experience` 체험 · `food` 먹거리 · `photo` 사진 명소

## 가정

- 이동 수단은 **자가용만**. 이동 시간은 두 장소 좌표의 직선거리에 도로 보정 1.4를 곱하고 평균 40km/h, 주차 · 걷기 5분을 더해 5분 단위로 올린다 ([ADR 0005](../00-overview/decisions/0005-day-plan-coordinates-hours.md)).
- 장소는 **청도군 안**만 다룬다 (관광 27 · 식당 8 · 카페 8, [`spots-data.md`](spots-data.md)). 출발지는 받지 않고 첫 장소에서 시작한다.
- 운영시간은 요일 규칙(`hours`)으로 일정 계산에 반영한다. 공휴일 · 명절 · 달마다 다른 휴무는 계산하지 않고 상세 화면 안내 문구로만 알린다.
- 서비스는 동작 중에 **TourAPI를 부르지 않는다**. 장소 데이터는 TourAPI로 조사한 뒤 직접 확인 · 작성한 JSON이다.

## 완료 기준 (Definition of Done)

- [ ] 배포된 HTTPS URL에서 F1 → F2 → F5 흐름이 동작한다
- [ ] 같은 URL을 다시 열면 같은 일정이 나온다 (결정적 알고리즘)
- [ ] `date=2026-02-30` 같은 잘못된 파라미터에 400 응답과 상태 화면이 나온다
- [ ] 없는 장소 id에 404 응답과 상태 화면이 나온다
- [ ] 휴무일인 장소, 마감 뒤 도착하는 장소가 일정에 들어가지 않는다
- [ ] 390px 폭(휴대폰)에서 가로 스크롤 없이 동작한다
- [ ] 키보드만으로 조건 선택과 이동이 가능하다 (버튼 `aria-pressed`, 포커스 표시)
- [ ] 일정 계산 단위 테스트와 API 테스트가 CI에서 통과한다
- [ ] `main`에 push하면 자동 배포된다
