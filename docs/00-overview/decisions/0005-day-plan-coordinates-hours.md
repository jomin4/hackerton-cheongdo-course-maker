# ADR 0005 — 하루 일정: 좌표 기반 이동 · 구조화 운영시간 · TourAPI는 조사 도구

- 상태: 승인 (2026-11-01)
- 대체한 결정: v1 알고리즘의 권역 단위 이동 시간(같은 권역 10분 · 다른 권역 25분)과 자유 문자열 운영시간
- 유지하는 결정: [ADR 0003](0003-json-instead-of-db.md) (DB 대신 JSON 파일 + 메모리 로드)
- 설계: [`../../01-product/day-course-design.md`](../../01-product/day-course-design.md)

## 맥락

v1은 "여행 시간 몇 시간 + 동행 + 관심사"를 받아 관광지 목록과 총 소요 시간을 줬다. v2는 자가용 당일 관광객에게 **시각이 적힌 하루 일정**(관광 · 점심 · 쉬어 가기 · 저녁 · 야간 관광)을 준다. 그러려면 세 가지가 v1 방식으로는 안 된다.

1. 권역은 9개 읍 · 면으로 늘었고, 같은 권역 안에서도 거리가 크게 다르다 (예: 운문면). 10분/25분 가정으로는 도착 시각을 적을 수 없다.
2. 몇 시에 도착하는지 알려 주려면 그 요일에 문을 여는지, 마감 전에 체류를 마칠 수 있는지를 계산해야 한다. 자유 문자열(`"09:30-18:00"`, `"매주 월요일"`)로는 계산할 수 없다.
3. 장소를 6곳 샘플에서 43곳으로 늘리려면 TourAPI(한국관광공사) 자료가 필요하다. 그런데 한국관광콘텐츠랩 저작권 정책은 **콘텐츠 캐싱(로컬서버 저장방식)을 금지**하고, 서비스가 동작 중에 TourAPI를 부르면 외부 장애 · 호출 한도에 서비스가 묶인다.

## 결정

- **이동 시간은 좌표로 어림한다.** 장소마다 `location`(WGS84)을 두고, 두 장소의 하버사인 거리로 계산한다.

  ```
  이동(분) = ceil5( 거리(km) × 1.4 ÷ 40km/h × 60 + 5 )   // 거리 0이면 0
  ```

  상수는 `packages/shared`의 `TRAVEL = { roadFactor: 1.4, speedKmh: 40, overheadMinutes: 5, roundTo: 5 }`. 권역(`zone`)은 표시 · 묶음용으로만 남긴다.
- **운영시간은 요일별 구조로 둔다.** `hours: WeeklyHours = { days: Record<Weekday, TimeRange[]>, lastEntryBeforeCloseMinutes?, note? }`. 빈 배열이 휴무, 쉬는 시간은 구간 2개. 모든 장소에 `hours` · `checkedAt` · `location`이 필수이고, 확인하지 못한 장소는 넣지 않는다. 요일 규칙 밖의 휴무는 `note`로 안내만 한다.
- **TourAPI는 오프라인 조사 도구로만 쓴다.** `tools/tourapi/`의 수집 스크립트 결과는 `.data-draft/`(git 제외)에만 둔다. 저장소 · 서비스에는 우리가 확인한 사실, 우리가 쓴 문장, 우리가 정한 값, 공공누리 제1유형 사진의 원본 URL과 출처(`credit`)만 넣는다. 재확인용으로 `sourceRef.contentId`를 남기고, 푸터에 "데이터 제공: ⓒ한국관광공사"를 표기한다. 서비스 동작 중 TourAPI 호출은 없다.
- **저장은 그대로 JSON이다.** `apps/api/data/spots.json` + 시작 시 zod 검증 · 메모리 로드, `SpotRepository` 인터페이스 유지 (ADR 0003).

## 근거

- 좌표 계산은 외부 API 없이 결정적이라, 같은 URL이 항상 같은 일정을 준다 (공유 보장, 테스트 가능).
- 도로 보정 · 평균 속도 · 주차 시간은 상수 3개라, 실제 길찾기 값과 비교해 조정하기 쉽다.
- 구조화 운영시간이면 휴무일 · 마감 · 입장 마감 · 쉬는 시간을 순수 함수(`fitVisit`)로 검사할 수 있고, 화면 문구(`formatWeeklyHours`)도 같은 데이터에서 만든다.
- TourAPI 원문을 저장하지 않으므로 저작권 정책을 지키고, 외부 장애가 서비스에 번지지 않는다.

## 대가

- 이동 시간은 어림값이라 실제 도로 · 교통과 다를 수 있다 → 결과 화면에 안내 문구를 둔다.
- 운영시간이 바뀌면 사람이 다시 확인해 `spots.json`과 `checkedAt`을 고치고 재배포해야 한다.
- 공휴일 · 명절 · 달마다 다른 휴무는 계산하지 못한다 (`note` 안내만).
- "상시 개방" 장소의 추천 관람 시간처럼 우리가 정한 값이 생긴다 → 근거를 PR 설명에 남긴다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| v1 권역 가정(10분/25분) 유지 | 도착 시각을 적을 수 없고 9개 읍 · 면 안의 거리 차이를 못 담음 |
| 길찾기 API · 실시간 교통 | 설계 비목표. 외부 호출에 묶이고, 같은 URL이 시점에 따라 다른 일정이 됨 |
| 운영시간을 자유 문자열로 두고 표시만 (v1) | 휴무일 · 마감 뒤 도착을 막을 수 없어 v2 목표와 맞지 않음 |
| 우리 필드(`contentId` · 태그 · 체류)만 저장하고 TourAPI 값은 실시간 조회 ([조사 문서](../../01-product/data-sources-research.md) 미결 사항 1의 (b)) | 서비스가 외부 장애 · 호출 한도에 묶임 |
| DB 도입 | 소유자 결정으로 JSON 유지. 읽기 전용 데이터라 ADR 0003의 근거가 그대로 유효 |
